# Feature Specification: Nearest Station Map SPA

**Feature Branch**: `001-nearest-station-map-spa`  
**Created**: 2026-05-28  
**Status**: Clarified  
**Input**: User description: "OpenStreetMap をベースにした「指定地点から近い最寄り駅を表示する Web サービス」。ユーザーが地図上の任意地点をクリックすると、その地点の周辺にある駅を OpenStreetMap データから検索し、距離が近い順に一覧表示する。商用利用なし。GitHub Pages または Vercel にデプロイできる静的 SPA。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 地図クリックで最寄り駅を探す (Priority: P1)

ユーザーが地図上の任意の地点をクリックすると、その地点の周辺にある駅が距離が近い順に一覧表示される。地図上にもクリックした地点と各駅候補のマーカーが表示され、どこにどの駅があるかを視覚的に確認できる。

**Why this priority**: アプリの中核機能であり、これ単体でサービスとして成立する。他のすべての機能はこの機能の拡張である。

**Independent Test**: アプリを開いて地図をクリックするだけで駅一覧が表示されれば、それだけで価値のある MVP として成立する。

**Acceptance Scenarios**:

1. **Given** アプリを開いて東京駅周辺の地図が表示されている状態で、**When** 地図上の任意の地点をクリックすると、**Then** クリックした地点に目立つマーカーが表示され、周辺の駅が距離順に最大 10 件まで一覧表示される。
2. **Given** 駅一覧が表示されている状態で、**When** 別の地点を地図上でクリックすると、**Then** 以前のクリック地点マーカーと駅一覧が新しいものに置き換わる。
3. **Given** 駅候補のマーカーが地図上に表示されている状態で、**When** 駅マーカーをクリックすると、**Then** 駅名と距離がポップアップで表示される。
4. **Given** 建物や山中などの駅が存在しない地点をクリックした場合、**When** 検索が完了すると、**Then** 「駅が見つかりませんでした」というメッセージが表示される。

---

### User Story 2 - 検索半径を変更して探す (Priority: P2)

ユーザーが検索半径（1,000m / 2,000m / 3,000m / 5,000m）を選択することで、探す範囲を自由に調整できる。近隣の主要駅だけ見たい場合は狭い半径を、山間部など駅が少ない地域では広い半径を使うことで、目的に合った検索ができる。

**Why this priority**: 地域によって駅の密度が大きく異なるため、検索範囲を変えられることで利用シーンが広がる。

**Independent Test**: 半径セレクターを変更した後に地図をクリックすると、変更後の半径で検索が行われることを確認できる。

**Acceptance Scenarios**:

1. **Given** アプリが表示されている状態で、**When** 検索半径を「1,000m」に変更して地図をクリックすると、**Then** 1,000m 以内の駅のみが一覧表示される。
2. **Given** アプリが表示されている状態で、**When** 検索半径を「5,000m」に変更して地図をクリックすると、**Then** 5,000m 以内の駅が一覧表示される。
3. **Given** 検索中の状態で、**When** 半径を変更しようとしても、**Then** 検索完了まで操作が無効化され、完了後に有効になる。

---

### User Story 3 - 現在地から最寄り駅を探す (Priority: P3)

「現在地から探す」ボタンを押すことで、デバイスの現在地を基点にした駅検索が行える。地図上で地点を探す手間なく、今いる場所の最寄り駅をすぐに確認できる。

**Why this priority**: ユーザーの最もよくある利用シーンである「今いる場所の最寄り駅を調べる」を最短手順で実現する。

**Independent Test**: HTTPS 環境でボタンを押して位置情報取得を許可すると、現在地周辺の駅が表示されることで確認できる。

**Acceptance Scenarios**:

1. **Given** HTTPS 環境でアプリを開いている状態で、**When** 「現在地から探す」ボタンを押して位置情報を許可すると、**Then** 現在地にマーカーが表示され、周辺の駅が一覧表示される。
2. **Given** 位置情報の許可を拒否した場合、**When** 「現在地から探す」ボタンを押すと、**Then** 「位置情報へのアクセスが拒否されました」というエラーメッセージが表示される。
3. **Given** 位置情報が取得できない環境（機内モードなど）で、**When** 「現在地から探す」ボタンを押すと、**Then** エラーメッセージが表示され、アプリはクラッシュしない。

---

### User Story 4 - 地図上で駅の場所を確認する (Priority: P4)

駅一覧の「地図で見る」ボタンを押すことで、地図が該当駅のマーカー位置までスクロール・ズームされ、その駅の地図上の位置を素早く確認できる。

**Why this priority**: 一覧表示された駅名だけでは場所のイメージがしにくいため、地図との連携で利便性が高まる。

**Independent Test**: 駅一覧の「地図で見る」ボタンを押すと地図がその駅の位置にアニメーション移動することを確認できる。

**Acceptance Scenarios**:

1. **Given** 駅一覧が表示されている状態で、**When** 任意の駅の「地図で見る」ボタンをクリックすると、**Then** 地図がその駅のマーカーの位置にアニメーション付きで移動する。

---

### Edge Cases

- 指定地点が陸地から遠く離れた海上など、周辺に駅が存在しない場合はどう表示するか？ → 「半径 Xm 以内に駅が見つかりませんでした」と表示する。
- 駅データに同じ駅が複数のデータ形式（ノード・エリア・リレーション）で重複して返ってきた場合はどう扱うか？ → 駅名と座標が近いものは同一駅とみなし、距離が短い方を残して重複を除外する。
- 検索中にネットワークが切断された場合はどう扱うか？ → エラーメッセージを表示し、アプリの状態を安定させる。
- 緯度・経度が有効範囲外（例：緯度±90°超・経度±180°超）の場合はどう扱うか？ → 入力を検証してエラーメッセージを表示する。
- Overpass API のレート制限（混雑・タイムアウト）に達した場合はどう扱うか？ → HTTP エラーとして補足し、ユーザーにわかりやすいメッセージを表示する。
- ネットワークが無応答でサーバーからレスポンスが返ってこない場合はどう扱うか？ → クライアント側 30 秒タイムアウト（FR-021）でリクエストを中止し、「検索がタイムアウトしました」等のメッセージを表示する。

## Clarifications

### Session 2026-05-28

- Q: 現在地検索後の地図移動 → A: 現在地検索のときだけ取得した現在地座標に地図を移動させる（ズームレベルは変えない）
- Q: クライアント側 fetch タイムアウト → A: `AbortController` で 30 秒のタイムアウトを設け、超過時にエラーメッセージを表示する

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは OpenStreetMap の地図タイルを使用してインタラクティブな地図を表示しなければならない。
- **FR-002**: 初期表示位置は東京駅周辺（緯度 35.681236 / 経度 139.767125）、ズームレベルは中程度でなければならない。
- **FR-003**: ユーザーが地図上をクリックすると、クリック地点に視認性の高いマーカーが表示されなければならない。
- **FR-004**: クリック地点から指定半径内にある駅を OpenStreetMap データから検索し、距離の近い順に最大 10 件表示しなければならない。
- **FR-005**: 対象とする駅タグは `railway=station`、`railway=halt`、`public_transport=station` を含まなければならない。
- **FR-006**: 検索半径は 1,000m / 2,000m / 3,000m / 5,000m の 4 段階から選択できなければならない。デフォルトは 3,000m とする。半径を変更しても自動再検索は行われず、次に地図をクリックした際に新しい半径が適用される。
- **FR-007**: 駅候補は地図上に番号付きマーカーとして表示されなければならない。
- **FR-008**: 駅候補マーカーをクリックすると、駅名と距離のポップアップが表示されなければならない。
- **FR-009**: 結果一覧には順位・駅名・距離（1,000m 未満は「xxx m」、1,000m 以上は「x.x km」）・OSM 種別を表示しなければならない。
- **FR-010**: 結果一覧の各駅に「地図で見る」ボタンを設け、クリックすると地図がその駅の位置に移動しなければならない。
- **FR-011**: ブラウザの位置情報 API を使用して現在地から検索できる「現在地から探す」ボタンを提供しなければならない。現在地取得に成功し検索が完了したら、取得した現在地座標に地図を移動させる（ズームレベルは変えない）。
- **FR-012**: 検索中はクリック操作とボタン操作を無効化し、ローディング状態をユーザーに明示しなければならない。
- **FR-013**: OpenStreetMap の著作権表示（attribution）を地図上に必ず表示しなければならない。
- **FR-014**: 駅が 0 件の場合・API エラー・ネットワークエラー・位置情報取得失敗のすべてにおいて、ユーザーにわかりやすいエラーメッセージを表示しなければならない。
- **FR-015**: アプリはエラー発生時にクラッシュしてはならない。
- **FR-016**: 画面レイアウトはデスクトップ（地図＋右サイドパネル）とモバイル（地図＋下部パネル）に対応しなければならない。
- **FR-017**: アプリはサーバーサイド処理なしに静的ファイルとして配信可能でなければならない。
- **FR-018**: 地図のパン・ズーム操作では駅の自動再検索を行ってはならない（ユーザー操作起点のみ）。
- **FR-019**: 地図クリックによる検索が完了した後は、地図の表示範囲（ズームレベル・中心位置）を自動調整しない。ユーザーが任意にパン・ズームして確認する。ただし「現在地から探す」による検索は例外とし、FR-011 に従い現在地座標に地図を移動させる。
- **FR-020**: 地図上のダブルクリックはズーム操作として扱い、駅検索は行わない。駅検索はシングルクリックのみを起点とする。
- **FR-021**: Overpass API への `fetch` リクエストにはクライアント側で 30 秒のタイムアウトを設けなければならない。30 秒以内に応答がない場合はリクエストを中止し、タイムアウトを示すエラーメッセージをユーザーに表示する。

### Key Entities

- **検索地点 (Search Point)**: ユーザーが指定した地点。緯度・経度を持つ。一度に 1 件のみ有効。
- **駅 (Station)**: OSM から取得した駅情報。識別子・駅名・座標（緯度・経度）・クリック地点からの距離・OSM タグ群・OSM データ種別（node / way / relation）を持つ。
- **検索条件 (Search Params)**: 検索地点と検索半径の組み合わせ。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 地図クリックから駅一覧表示まで、通常のネットワーク環境で 10 秒以内に完了する（Overpass API 応答時間による）。
- **SC-002**: 東京・大阪などの主要都市で地図をクリックすると、周辺の駅が距離順に正しく表示される。
- **SC-003**: デスクトップ・スマートフォンの両方で、追加の操作なく地図と結果一覧が同時に表示される。
- **SC-004**: `npm install` → `npm run build` が追加設定なしで成功し、生成された静的ファイルを GitHub Pages または Vercel にそのままデプロイできる。
- **SC-005**: API エラーや 0 件の場合に、アプリがクラッシュせずユーザーへのメッセージ表示で正常終了する。
- **SC-006**: 地図上でパン・ズームを繰り返しても、ユーザーが地図をクリックしない限り API リクエストが発生しない。

## Assumptions

- Overpass API（`overpass-api.de`）は無料・公共インスタンスを使用する。高負荷時は応答が遅延・失敗することがある。
- 検索半径の変更は即時の再検索を引き起こさない。ユーザーが次に地図をクリックした際に新しい半径が使用される。
- 地図クリックによる検索完了後は地図の表示範囲を変更しない。「現在地から探す」による検索完了後のみ、現在地座標に地図を移動させる（ズームレベルは変えない）。
- ダブルクリックは OpenLayers のデフォルト動作（ズームイン）として扱い、検索トリガーにはならない。
- Overpass API 呼び出しにはクライアント側 30 秒タイムアウトを設ける。サーバー側クエリの `[timeout:25]` に 5 秒の余裕を持たせた値とする。
- 現在地機能は HTTPS 環境でのみ動作する（ブラウザ仕様）。
- 地図の初期位置は東京駅周辺とするが、ユーザーが自由にパン・ズームできる。
- 非商用・個人利用を前提とし、Overpass API の利用規約に準拠した範囲で使用する。
- データ永続化（お気に入り保存など）は MVP スコープ外とする。
- OSM データの品質・更新頻度はサービス提供者（OpenStreetMap）に依存する。
